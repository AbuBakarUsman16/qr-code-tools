Styling costs you reliability. This tool shows you how much

Every decoration you add to a QR code takes something away from its ability to be read. A logo covers modules. Low contrast makes the camera work harder. Dot shapes shrink each module slightly. None of that is a reason never to style a code, but it is a reason to know where the line is.

Most styling tools let you sail past that line and find out at the printers. This one decodes your styled code on every change and tells you straight away whether it still works, using the same method we used for our damage testing.

The check under the preview is the point of this tool. It is not a guess or a rule of thumb. We run a real decoder over the image you are looking at and report what comes back.

Getting a logo right

  1. Use a simple mark, not a full logo with text. Small text inside a QR code is unreadable anyway and wastes the area you are spending.
  2. Prefer a transparent PNG or a square mark. The tool places a background coloured pad behind it so the edges stay clean.
  3. Start at 12% and increase only if you need to. Smaller logos leave more error correction budget for print imperfections, which is where codes actually fail.
  4. Print larger than you would without a logo. You have spent the redundancy on decoration and have none left for a scuff or a fold.

Colour choices that survive contact with reality

The safe rule is dark modules on a light background. Within that, brand colours are usually fine if the dark side is genuinely dark. What breaks:

  • Inverted codes. Light modules on a dark ground look striking and fail on a meaningful share of scanners. Our test could not decode one at all.
  • Mid tone on mid tone. Two colours that look different to your eye can be close in luminance, which is what the camera actually measures.
  • Gradients. Contrast varies across the pattern, so part of the code is always the weakest link.
  • Transparent backgrounds. The code ends up over a photo or a coloured panel and the contrast becomes unpredictable.

Frames and why they help more than styling does

If you want a code to get scanned more often, a frame with a short instruction does more than any amount of visual styling. An unlabelled code on a poster gets very few scans, because people do not scan things when they do not know what will happen.

"Scan for the menu" outperforms a beautifully styled unlabelled code, every time. The frame here adds that line without touching the code area.

Test the printed version, not just the preview

The check in this tool decodes a clean digital image, which is the most forgiving case. A phone camera pointed at printed paper in a dim room is a harder test.

So before a print run: print one at final size on the real stock, and scan it with an ordinary phone, at the real distance, at an angle. A styled code that passes that has earned its decoration. Our print sizing guide covers the numbers.

Common questions

Why does the tool force level H when I add a logo?

Because anything lower fails almost immediately once modules are covered. In our testing, level M managed 8% of its area covered while H managed 19%. With a logo you need every bit of that budget.

Why can I not style the three corner squares?

They are position markers, and the scanner uses them to locate the code before reading anything. We tested this: removing a single module from one corner killed a code that had shrugged off 19% of damage elsewhere. Styling them is a popular feature elsewhere and a bad idea.

Do dot and rounded styles reduce scannability?

Slightly, because each module ends up marginally smaller than a full square. At normal print sizes it rarely matters. At small sizes, use squares.

My code says it does not scan. What now?

In order: reduce the logo, raise the contrast, switch back to square modules, and check you have not inverted the colours. The check updates as you change each one, so you can find the specific culprit rather than guessing.
