Why not use the app's own QR code?

Instagram, Snapchat and TikTok all generate a code inside the app, and those work well for one specific situation: two people standing together, one holding a phone. Outside that, they have real limits.

In app codeProfile link code
Scanned from printAwkward, you have to screenshot itDesigned for it
Works without the app installedNoYes, opens the web profile
Same code for every platformNo, one per appYes, same format
Print at any sizeLimited by the screenshotYes

The last row is the one that matters for anything printed. A profile link code scans for everyone, whether or not they have the app, because it falls back to the website.

Getting the username right

Each platform builds profile URLs differently, which is the part people get wrong. This tool handles it, but it is worth knowing what it is doing:

PlatformURL format
Instagraminstagram.com/username
TikToktiktok.com/@username
YouTubeyoutube.com/@handle
Facebookfacebook.com/pagename
Xx.com/username
LinkedInlinkedin.com/in/profile
Snapchatsnapchat.com/add/username
Spotifyopen.spotify.com/user/id
Discorddiscord.gg/invite code

Note that TikTok and YouTube need the @ and the others do not. Paste your username either way, with or without an @, and it will be corrected.

Check the link before you print. Type your username, then click the link preview under the field and make sure it lands on your profile. A username that looks right but has a stray character produces a perfectly scannable code pointing at nothing.

Where these belong

  • Business cards. One code on the back beats four social icons nobody types in.
  • Shop windows and counters. Follows happen in the moment or not at all.
  • Product packaging and inserts. Reaches the customer at home, when they have time.
  • Market stalls and events. Where the conversation ends but the relationship could continue.
  • Van livery and signage. For trades whose work is visual, a portfolio feed is the sales pitch.

One caution: one code, one platform. Printing five codes side by side means people scan none of them. Pick the account you actually post on.

Common questions

Will it open the app or the browser?

If the app is installed, phones almost always hand the link to the app. If not, the web profile opens, which is the right fallback and one the in app codes do not have.

Can I link to a specific post instead of my profile?

Yes, but use the URL generator for that and paste the full post link. Post URLs are long, which makes a denser code, so print it larger.

What if I change my username?

The old code stops working, because the username is inside the image. Platforms rarely redirect old handles. Anything printed in quantity is worth pointing at a page you control instead, which then links out.

Does this work for a Facebook group or business page?

Yes, as long as the page has a custom username rather than a numeric ID. If yours still shows a long number, set a username in the page settings first, and the code stays valid afterwards.

Why a single code beats a row of icons

Printed material often carries five social icons with usernames beside them. Almost nobody types those in. The action is too slow for the payoff, and by the time the card is in a pocket the intention is gone.

A single code converts better for a simple reason: the gap between wanting to follow and following is one scan rather than switching apps, searching a name, and picking the right account from three similar results.

That also means the choice of which platform matters. Pick the account you post on most, not the one with the largest follower count, because a follower who arrives at a dormant feed does not come back.

Measuring whether it works

Static codes carry no analytics, but you do not need them here. Note your follower count on the day the printed material goes out, then again two weeks later. Against a stable baseline, the difference is the answer.

If you want something more precise, point the code at a page on your own site that links onward to the profile. Your normal analytics then show the visits, and you keep the ability to change where it goes later, without depending on a paid dynamic code service.
